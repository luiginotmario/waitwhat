# 3D scenes: the 3b1b look, in depth

Some physical "how does X work" ideas are about **structure in depth**: what a touchscreen is made
of, what is inside a battery, how a ripple spreads over water, why a tilted axis makes seasons.
For those, a scene can be 3D, drawn exactly the way Grant draws 3D: shaded solids and surfaces in
the palette colours, a camera that orbits or tilts, flat labels on top. Same Manim, same render,
same cost class as a 2D scene. Everything here is in the style lib (`from waitwhat_style import *`
gives you `WaitwhatScene3D` and the helpers below).

## When to use 3D (rarely)

Use it only when **depth itself explains something**: layers stacked on top of each other, an
inside hidden by an outside, a surface's height over a plane, an orbit's tilt. Then one or two
3D scenes in a video, usually the ones where the structure is revealed. Everything else stays 2D:
flows, causes, numbers, comparisons, timelines, formulas. A 2D cross-section is often clearer than
a 3D object (a circuit, a single cell under a microscope, a lens diagram): prefer it unless the
viewer must see how the parts sit in space.

The plan says so per scene: `"dim": "3d"` in `plan.json` (the default is 2D; see the waitwhat
skill's planning). A 3D scene gets `class X(WaitwhatScene3D)` and this reference.

## The skeleton

```python
from waitwhat_style import *

class Inside(WaitwhatScene3D):                   # house view: VIEW_PHI 64°, VIEW_THETA -58°
    def construct(self):
        cell = cutaway([("can", "GREY", 1.25), ("cathode", "RED", 1.1), ("anode", "BLUE", 0.7)])
        self.view(zoom=1.2, shift=SAFE_CENTER + LEFT * 1.4)       # frame it; room for labels
        self.play(rotate_reveal(cell), run_time=self.until("cell"))
        self.wait_until("open")
        self.camera_to(phi=70 * DEGREES, added_anims=[cell.open()], run_time=1.8)
        for c, mark in zip(self.label_layers(cell, names=["cathode", "anode"]), ["cathode", "anode"]):
            self.wait_until(mark)
            self.play(c.enter())
        self.finish()
```

Everything WaitwhatScene gives still works: bookmark timing (`until`, `wait_until`, `play_until`,
`finish`), sound cues (auto and `sfx=`), the theme painted behind, both aspects, the layout lint.
Angles are radians (`70 * DEGREES`), as everywhere in Manim.

## API

| Call | Does |
| --- | --- |
| `class X(WaitwhatScene3D)`, class attrs `view_phi`, `view_theta`, `view_zoom` | the scene; starts at the house view (`VIEW_PHI`, `VIEW_THETA`), or flat (`FLAT_PHI`, `FLAT_THETA`) |
| `self.view(phi, theta, zoom, look_at, shift)` | set the camera now; `look_at` = world point at the centre, `shift` = where on screen the picture sits (default `SAFE_CENTER`) |
| `self.camera_to(phi, theta, zoom, look_at, shift, run_time=2.5, added_anims=[...])` | eased camera move (smooth), other animations ride along |
| `self.orbit(by=PI/4, run_time=4, dphi=0)` | swing around the vertical axis (+ tilt) |
| `self.dolly(zoom, run_time=2, look_at=None)` | push in / pull out |
| `self.drift(rate=0.06)` / `self.stop_drift()` | slow ambient rotation that eases in and out and runs through waits |
| `self.fit_zoom(mob, fill=0.8, phi, theta, below)` | the zoom at which mob fills the free safe area from that view |
| `self.light_from(point, ambient)` / `self.light_from()` | light from a world point (a sun: day and night sides) / back to the viewer's headlight |
| `self.fixed(*mobs)` / `self.hud(*mobs)` | flat on the screen (titles, formulas, counters): register / register and add |
| `self.tag(label, obj, direction=DOWN)` | a name next to a 3D object's on-screen outline, following it at any zoom |
| `self.pin(label, anchor, offset=UP*0.45)` | a flat label following a 3D point (anchor: a Mobject, a point, or a function) |
| `self.callout(text, anchor, at=None, side=RIGHT)` | a flat label + leader line + dot on a 3D point; `.enter()`, `.leave()` |
| `self.label_layers(stack_or_cutaway, names, texts, side)` | callouts in a tidy column beside the object, never overlapping |
| `self.label_column([(text, anchor), ...], side)` | the same for any set of 3D points |
| `self.axis_labels(ax, "x", "y", "z")` | flat axis letters pinned past the tips |
| `self.to_screen(point)` | where a 3D point is on screen now |
| `self.particles(path, n, speed, color)` | glowing dots streaming along a 3D path (charge, blood, ions, air) |
| `self.ripples(center, normal, n, max_radius, period)` | expanding rings (sound, a touch, a field spreading) |
| `self.animate_surface(s, run_time)` / `self.keep_surface_moving(s)` | run a live surface in time |
| `surface(f(u,v), u_range, v_range, color, resolution=18)` | parametric surface, checkerboard of the colour and its darker cousin |
| `graph_surface(f(x,y), x_range, y_range, color, live=False)` | z = f(x, y); `live=True`: f(x, y, t) that moves in place, cheaply |
| `ball(r, color, at)`, `slab(w, d, h, color, at)`, `cylinder(r, h, color, direction)` | light solids in the house look |
| `axes3d(x_range, y_range, z_range)` | thin grey axes, small tips, no numbers |
| `exploded_layers([(name, COLOR[, thickness]), ...])` | stack of plates (top first): `.explode(gap)`, `.assemble()`, `["name"]`, `.anchors` |
| `cutaway([(name, COLOR, radius), ...], kind="cylinder"\|"sphere", height, cut)` | layered solid with a wedge: `.open()`, `.close()`, `.anchors` |
| `rotate_reveal(mob, angle=-PI/2, axis=OUT)` | entrance: turns into place while fading up |
| `glow_path(path, color, depth=False)`, `orbit_path(radius, ecc, tilt)` | a glowing vector-style path; an orbit |
| `depth_sorted(mob)`, `bleed(mob)`, `keep_safe(mob)`, `tone(color)` | let flat things take part in the depth sort; allow running off-frame; clamp a flat thing into the safe area; checker cousin |

Colours are palette names (`"BLUE"`, `"GREY"`, `"INK_3"`) or `color_of(...)` concepts, as in 2D.

## Camera grammar

- **One idea per move.** A move reveals something (the inside, the tilt, the height). Move, then
  hold still while the narration explains: a still camera also renders almost for free.
- **Start flat, then tilt.** A 3D scene at `FLAT_PHI, FLAT_THETA` looks exactly like 2D, so it can
  continue straight from a 2D scene (`"transition": "continuous"`), then tilt on the word that
  needs depth. That tilt is the most 3b1b move there is.
- **House view** for objects: `VIEW_PHI` 64°, `VIEW_THETA` -58° (above, right-front). Lower phi
  (40–55°) looks down more (flat things read taller), higher (70–80°) looks from the side
  (layers, heights).
- **Moves**: 1.5–3 s with the smooth ease (`camera_to`), orbits by 20–60° (`orbit(PI/6)`), not full
  turns. A drift (`drift(0.05)`) only under a stretch of narration that has nothing else moving,
  stopped when the next idea starts.
- **Ride along**: combine the move with the change it shows (`added_anims=[stack.explode(0.9)]`),
  so the camera seems to follow the action.
- **Light**: the default headlight (from the viewer's upper left) keeps solids readable from any
  angle. `light_from(point)` only when the light source is in the story (a sun, a lamp).

## Labels and text: always flat on the screen

Text never lives in 3D space: it skews, shrinks and hides behind solids. The lint flags it
("text in 3D space"). Use:
- `tag(label, obj, direction)` for an object's name (it clears the object at any zoom);
- `pin(label, point)` for a point (it follows; offsets are screen units);
- `callout(text, point)` or `label_layers(...)` when labels sit beside the object with leader
  lines: the 3b1b way to name the parts of something;
- `fixed(...)`/`hud(...)` for titles, formulas and counters that don't belong to an object.

Labels that follow moving things are clamped into the safe area, and the lint still checks overlaps
between them. One label per object at a time: when a new fact about the same object arrives, the
old label leaves (`FadeOut(old)`, `enter(new)`). Enter labels while the camera holds still.

## Patterns

- **Exploded layers** (`templates/exploded_layers.py`): whole object turns in (`rotate_reveal`) →
  `stack.explode(gap)` with a small camera move → `label_layers` one per bookmark → dim the others
  (`l.animate.set_opacity(0.18)`) and show what the key layer does. Decorate a layer by adding to
  it (`stack["touch sensor"].add(depth_sorted(grid))`): it moves with the layer. A glass layer
  reads well at opacity 0.3.
- **Cutaway** (`templates/cutaway.py`): `cutaway([...])` → `rotate_reveal` → `cut.open()` (the
  wedge slides out, the cut faces appear) → labels on the cut face → the process inside
  (`particles` along a path on the cut face). The opening faces the house view by default; for
  another view pass `start = theta - cut / 2 + 25°`.
- **Surface or field** (`templates/surface_wave.py`): start flat, tilt; `graph_surface(f, live=True)`
  and `keep_surface_moving` for waves; track one point with a pinned marker and a callout, so the
  viewer sees what a single point does. Time the motion from the bookmarks
  (`speed = distance / (self.mark_time("there") - self.now)`) so the picture agrees with the words.
- **Orbit** (`templates/orbit.py`): flat orbit first, tilt to show the axis, `light_from(sun)`,
  a `ValueTracker` angle with an updater for the motion, timed so the planet is in the right place
  on the right word.
- **Invisible physics**: `particles(path)` for things that flow (current, ions, blood, air),
  `ripples(center)` for things that spread (sound, a touch, a field), `glow_path(path)` for a route
  or a field line. They are drawn in the classic vector style, flat and glowing, never photoreal.

## Performance budget

Measured on this machine (Cairo, 1080p30, Manim CE 0.22):

| Scene | Render | Video |
| --- | --- | --- |
| 2D templates (flow, sweep, proof, comparison) | 2.1–4.0 s | 12 s |
| `exploded_layers.py` (40 faces, 9 s of motion) | 3.5–3.9 s | 17 s |
| `cutaway.py` (150 faces, 12 s of motion) | 5.2–5.8 s | 19 s |
| `orbit.py` (390 faces, moving the whole scene) | 8.1–9.7 s | 17 s |
| `surface_wave.py` (640 faces, live surface for 14 s) | 8.3–9.2 s | 16 s |
| same surface + sphere, 6 s camera move: stock ThreeDScene / WaitwhatScene3D | 16.5 s / 4.8 s | 10 s |

A frame where something 3D moves costs about **25 µs per face**; a frame where nothing 3D moves
costs almost nothing (Manim reuses it). So the cost is faces × seconds of 3D motion. Rules:
- **Faces on screen ≤ 1500** (`FACE_BUDGET`); typical scenes use 50–700.
- **Resolutions**: `surface`/`graph_surface` 18 by default, **24 at most** (576 faces); `ball`
  (20, 12), small balls (10, 6); `cylinder` 20 sides (one band: height needs no subdivisions);
  never Manim's `Sphere()` default in bulk, never a resolution above 32.
- **Motion ≤ ~12 s per scene** at ~600 faces (`MOTION_BUDGET`), more for light scenes: camera moves
  1.5–3 s each, drifts and live surfaces stopped when their point is made
  (`s.clear_updaters()`, `stop_drift()`).
- The render's JSON reports `layout_issues` with "render budget" when the estimate passes
  `RENDER_BUDGET` (15 s) or the faces pass 1500; `logs/<id>.layout.json` has `perf`
  (`faces_max`, `motion_s`, `est_render_s`).
- Themes with ambient motion (`space`, `ocean`, `city`, `hills`) redraw every frame, so a 3D scene
  on them costs ~1.5x; fine within the budget.
- The OpenGL renderer does work headless here (~6x faster raw), but it can't paint the themes,
  handles text and fixed-in-frame objects differently and isn't what `ww render` runs: don't use it.

## 9:16 framing

- The world origin sits at `SAFE_CENTER` (above the phone UI band) by default; the lint checks
  that 3D objects stay inside the frame and text stays out of the bottom band.
- Frame with `fit_zoom(obj, fill)` for the view you are going to, instead of guessing a zoom.
- **Look from higher in 9:16**: wide flat things (a plane, an orbit, a board) project short from the
  house view and leave the tall frame empty. Use phi 45–55° there (`by_aspect(VIEW_PHI, 48 * DEGREES)`).
- Tall things (a cell, a stack exploded with a bigger gap: `by_aspect(0.95, 1.8)`) suit 9:16 well:
  zoom in further.
- Labels: a column on the right, the object shifted left (`shift=SAFE_CENTER + LEFT * 1.0`), and
  two-line labels (`texts=[by_aspect(n, n.replace(" ", "\n")) ...]`).

## Pitfalls (Manim 3D on Cairo)

- **Depth is per face, by centre**: shaded faces are sorted by their centre's depth; non-shaded
  things (lines, text, dots) are drawn on top of everything. To let a solid hide a line or path,
  `depth_sorted(...)` it, and build long paths from pieces (`glow_path(..., depth=True)`).
  Coplanar faces flicker in order: leave a hair of gap (0.01) between touching layers.
- **Opacity is not depth**: semi-transparent solids show what is sorted behind them, which can
  look wrong in heavy overlaps. Keep one or two transparent things (glass), not five.
- **Don't** use `frame_center`/`ThreeDScene.set_camera_orientation(frame_center=...)`: aim with
  `view(look_at=...)` / `camera_to(look_at=...)`, place with `shift`.
- **Don't** add text with `self.add(Text(...))` in a 3D scene (it is projected): `fixed`, `tag`,
  `pin`, `callout`. `add_fixed_in_frame_mobjects` works too, but adds at once (no entrance).
- `Transform` between flat labels: register the target first (`self.fixed(new)`), or simply
  `FadeOut(old)` + `enter(new)`.
- Mobjects that follow the camera use updaters: label entrances with `callout.enter()` keep them in
  sync; a plain `FadeIn(label)` freezes the label while it fades (fine when the camera is still).
- Never store the scene on a mobject (animations deep-copy mobjects): close over it in a lambda.
- Giving a VGroup subclass attributes named `width`, `height`, `color` or `target` resizes or
  breaks it: these are Mobject properties.
- An updater that moves solids or the camera makes every frame a full redraw, waits included:
  remove it when its job is done.
- `Sphere()` defaults to 24 × 12 faces, `Cylinder()` to 24 × 24, `ThreeDAxes` tips are cones: use
  the house constructors, which are sized for the budget.
- A scene id that equals a Python module (`wave`, `math`, `random`, `types`, `code`) breaks the
  import of Manim itself (scene files are on the path): `ripple`, not `wave`.
